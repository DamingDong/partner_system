## 🎯 核心业务需求确认

### 1. 业务定位和角色模型
- **系统核心价值**: 会员卡预售全生命周期管理
- **目标用户**: 
  - 系统管理员（配置渠道编码和全局管理）
  - 渠道方案商（一级代理，管理会员卡池和绑定）
  - 酒店运营商（一级代理，管理酒店设备绑定）
  - 二级客户（不直接操作系统，由一级代理代操作）

### 2. 核心业务流程
```
渠道方案商/酒店运营商 → 会员卡池管理 → Excel导入绑定MAC地址 → 关联二级客户渠道编码
↓
用户APK激活/设备开机激活 → API状态同步 → 激活数据展示 → 订单管理 → 线下对账
↓
会员权益回收池 → 回收管理 → 满足条件可兑换新卡
```

### 3. 关键业务规则确认

#### 3.1 会员卡分配机制
- **方式**: 一级代理通过Excel导入绑定MAC地址
- **操作**: 批量导入和单个操作都支持
- **流程**: 二级客户提供MAC地址，一级代理代操作

#### 3.2 设备绑定规则
- **绑定方式**: 一个MAC地址可绑定多张会员卡
- **操作支持**: 批量导入和单个绑定
- **Excel模板规范**: 固定列名和顺序（MAC地址、渠道编码、备注）
- **MAC地址校验**: 标准格式验证和重复检查
- **错误处理**: 绑定失败时给出MAC地址和原因，支持下载错误报告
- **操作历史**: 记录导入操作和单条操作的历史记录
- **回收限制**: 单个MAC地址最多回收3次

#### 3.3 激活状态同步
- **同步方式**: 通过API接口与外部系统对接
- **同步时机**: 实时/准实时同步
- **数据来源**: APK激活和酒店设备开机激活

#### 3.4 数据权限管理
- **权限原则**: 上级可查看下级数据，同级数据隔离
- **安全控制**: 用户敏感信息和卡密采用中间部分星号替代

#### 3.5 订单管理规则
- **激活订单**: 不显示金额，仅用于记录激活行为
- **订阅订单**: 显示实际金额，用于对账
- **导出功能**: 支持Excel导出，用于线下对账

#### 3.6 会员权益回收池
- **回收方式**: 批量/单条MAC地址回收
- **累计逻辑**: 回收天数累计到分类权益池
- **兑换规则**: 满足条件（如年卡365天）可兑换新卡
