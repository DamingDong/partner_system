# 产品经理技能指南 - EPIC文档与用户故事对齐

## 📋 概述

本文档为产品经理提供确保EPIC文档与用户故事、业务规则对齐的方法论和最佳实践。

## 🎯 对齐检查清单

### 1. EPIC与用户故事映射检查

#### 1.1 用户故事覆盖度检查
```markdown
检查项：
- [ ] EPIC中列出的用户故事是否在用户故事库中存在
- [ ] 用户故事库中的相关故事是否都被EPIC覆盖
- [ ] 用户故事的状态与EPIC开发计划一致
- [ ] 用户故事的优先级与EPIC优先级匹配
```

**当前项目问题分析：**
- REVENUE_SHARING.md中引用了US-005, US-006, US-013等用户故事
- 但用户故事库中缺少US-013: 分账规则配置（状态：待分析）
- 需要确保所有引用的用户故事都有明确定义

#### 1.2 用户故事完整性检查
```markdown
检查项：
- [ ] 每个用户故事都有明确的角色定义
- [ ] 用户故事描述符合"作为...我想要...以便于..."格式
- [ ] 验收标准完整且可验证
- [ ] 用户故事有明确的优先级和状态
```

### 2. EPIC与业务规则对齐检查

#### 2.1 业务规则引用检查
```markdown
检查项：
- [ ] EPIC中引用的业务规则编号是否在业务规则文档中存在
- [ ] 业务规则描述与EPIC实现一致
- [ ] 业务规则的例外情况在EPIC中有考虑
- [ ] 业务规则的验证逻辑在技术需求中有体现
```

**当前项目问题分析：**
- REVENUE_SHARING.md中引用了BR-021到BR-025业务规则
- 但业务规则文档中这些规则编号缺失
- 需要确保业务规则编号的一致性和完整性

#### 2.2 业务规则实现检查
```markdown
检查项：
- [ ] EPIC的技术需求部分体现了业务规则要求
- [ ] 数据模型设计符合业务规则约束
- [ ] API接口规范包含业务规则验证
- [ ] 异常处理机制覆盖业务规则异常场景
```

## 🔧 对齐方法论

### 3. 三向对齐框架

#### 3.1 业务价值对齐
```markdown
业务目标 ←→ EPIC业务价值 ←→ 用户故事业务价值
```
**检查要点：**
- EPIC的业务价值描述是否清晰
- 用户故事是否支持EPIC的业务价值
- 业务规则是否保障业务价值的实现

#### 3.2 功能范围对齐
```markdown
EPIC功能范围 ←→ 用户故事功能点 ←→ 业务规则约束
```
**检查要点：**
- EPIC的功能范围是否被用户故事完整覆盖
- 用户故事的功能点是否在EPIC范围内
- 业务规则是否对功能实现有约束

#### 3.3 技术实现对齐
```markdown
EPIC技术需求 ←→ 用户故事验收标准 ←→ 业务规则验证
```
**检查要点：**
- 技术需求是否支持用户故事验收标准
- 验收标准是否可验证业务规则
- 业务规则验证是否在技术实现中体现

### 4. 版本一致性管理

#### 4.1 文档版本同步
```markdown
EPIC版本 v1.0 ←→ 用户故事版本 v1.0 ←→ 业务规则版本 v1.0
```
**检查要点：**
- 所有相关文档版本号一致
- 变更记录相互引用
- 版本发布时间协调

#### 4.2 变更影响分析
```markdown
变更类型：
- 业务规则变更 → 影响EPIC技术需求 → 影响用户故事验收标准
- 用户故事变更 → 影响EPIC功能范围 → 影响业务规则适用性
- EPIC范围变更 → 影响用户故事覆盖 → 影响业务规则应用
```

## 🚀 最佳实践

### 9. 文档维护最佳实践

#### 9.1 版本控制策略
- 使用语义化版本号（如v1.0.0）
- 建立变更日志机制
- 定期进行文档评审和更新

#### 9.2 协作流程
- 产品经理负责EPIC和用户故事对齐
- 业务分析师负责业务规则定义
- 技术负责人负责技术实现对齐
- 定期进行跨职能评审

### 10. 质量保证措施

#### 10.1 评审检查点
- **需求评审**: EPIC与用户故事对齐检查
- **设计评审**: 技术需求与业务规则对齐检查
- **验收评审**: 实现与验收标准对齐检查

#### 10.2 度量指标
- **对齐度**: 文档间引用完整性
- **一致性**: 相同概念在不同文档中的一致性
- **时效性**: 文档更新及时性
